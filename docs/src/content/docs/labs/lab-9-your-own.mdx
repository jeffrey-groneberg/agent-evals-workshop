## Choose a good first target

Pick something that's **used often**, **small**, and **has failed before** in a way you remember. A good first task has a clear right answer that two colleagues would agree on. Avoid tasks where "good" is mostly taste; add those once you have a calibrated judge.

## The loop, one more time

<Steps>

1. **Define good** (Lab 1). Write down four to six criteria before you run anything, including at least one must-not. Mark which ones code can check.

2. **Draft the eval.** Start from the template, or ask Copilot to draft it (Lab 6) and review the draft against your criteria:

   ```bash
   cp lab-files/lab-9/my-first.eval.yaml evals/
   ```

   Replace every `TODO`: the skill's folder, the files it needs, a realistic prompt, and checks for your criteria.

3. **Check your checks** (Lab 2). Make a copy with `executor: mock`, put a known-good answer and a known-bad answer into the prompts, and confirm the verdicts. Keep only the checks on the answer in that copy: a mock run makes no tool calls and changes no files, so checks on the transcript, such as `skill-invocation`, can't pass there.

4. **Run trials** (Lab 3): `vally lint -e evals/my-first.eval.yaml --strict`, then `vally eval -e evals/my-first.eval.yaml`. Read the transcripts, not only the pass rate.

5. **Fix and prove** (Lab 4). Change one thing, and compare with an experiment.

6. **Judge what code can't** (Lab 5). Add a rubric and a judge only for the criteria that need judgment, and calibrate it first.

7. **Guard it** (Lab 7). Tag the eval `lane: ci` and let every pull request run it.

</Steps>

## Tips from the workshop

- **Don't name the skill or the answer in the prompt.** Write the request a real user would type.
- **Add a negative check for every bug you've seen.** Bugs tend to be something extra.
- **Check the transcript and the workspace** where it matters, not only the answer.
- **Keep runs isolated.** Sign in with a token, not with `EVALUATE_USE_HOST_COPILOT_HOME=1`, so your own skills and settings don't leak into the run.
- **Start with three trials;** use more before you decide anything that matters.
- **Turn every real failure into a new task or control.** Your eval gets better with every bug it catches.
